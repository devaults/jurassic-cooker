# 角色卡：UI 设计

> 主导阶段：**界面设计**。负责把 PRD 变成可走查的 UI 稿 + 交互规范。

---

## 一、这个角色是谁

UI 设计的核心不是"画好看的图"，而是：

1. **信息架构** —— 让用户一眼找到要操作的东西
2. **交互流程** —— 让操作顺畅、不出错、可撤销
3. **视觉规范** —— 一致性大于个性
4. **可走查性** —— 开发能照着做、QA 能照着验

AI 在 UI 阶段是**模式参考 + 走查清单生成器**：把已有组件库能力映射到 PRD 场景、把 UI 稿拆成开发能验收的 checklist。

---

## 二、AI 放大点（这个角色最该让 AI 干的事）

| 任务 | 为什么适合 AI | 典型提示词信号 |
|---|---|---|
| 把 PRD 拆成 IA 树 | 信息整合、模板化 | "基于 PRD v[N]，输出页面/模块层级 IA" |
| 找现有组件库能用的组件 | 跨 `jurassic-ui`/`element-plus` 检索 | "本场景能用 jurassic-ui 哪些组件 ..." |
| 生成 wireframe 文案描述 | 结构化输出 | "把核心路径转成每个页面的 wireframe 描述" |
| 写走查 checklist | 不漏项 | "列出本 UI 设计的所有验收点（视觉/交互/可访问性）" |
| 对照品牌规范自检 | 模式匹配 | "检查本页是否符合 juraTheme 主题规范" |

---

## 三、判断红线（AI 不能干的部分）

| 判断 | 为什么必须人 |
|---|---|
| **视觉风格定调** | 涉及品牌调性、用户情感 |
| **关键决策的视觉强调** | 影响用户行为引导 |
| **可访问性兜底** | 残障用户场景需真实用户验证 |
| **跨页面一致性签字** | 需要看完整产品全局 |
| **UI 稿签字** | 责任归属 |

---

## 四、阶段产物清单（UI 阶段必须交付）

```markdown
UI Spec v[N] - [功能名]
├─ 1. 信息架构（IA 树：页面/模块/操作）
├─ 2. 关键页面 wireframe（每个核心路径至少一张）
├─ 3. 交互流程图（核心路径 + 异常路径 + 空状态 + 错误状态）
├─ 4. 组件清单（用 jurassic-ui/element-plus 哪些组件）
├─ 5. 视觉规范（间距/字号/颜色，对照 juraTheme）
├─ 6. 响应式断点（桌面/平板/手机）
├─ 7. 文案规范（中英文、i18n key 列表）
├─ 8. 走查 checklist（视觉/交互/可访问性/边界）
├─ 9. 签字 + 版本号
└─ 10. 给接口架构师（API 契约阶段）的下一步指令
```

## 五、调用 AI 的最小提示词模板

> 完整模板见 [`../prompts/stages/02-ui.md`](../prompts/stages/02-ui.md)。

```markdown
# 角色
你是有 5 年 B 端 UI 设计经验的设计师，熟悉 jurassic-ui 2.x 组件库与 juraTheme 主题。

# 当前阶段
界面设计。我要把 PRD v[N] 拆成 UI Spec v1。

# 输入物
- PRD v[N]：[链接或粘贴]
- 项目上下文：<项目名（仓库名，如 oio-master-web；不写 group/ 前缀，见使用方项目注册表）>
- 技术栈：Vue 3 + Vite + TS + jurassic-ui 2.x（或其它）
- 必须读取：
  - .trae/skills/frontend/jurassic-ui/SKILL.md（组件能力地图）
  - .trae/rules/frontend/lang/css.md（CSS 规范）
  - .trae/skills/frontend/i18n-workflow/SKILL.md（如有国际化）

# 输出物
按 UI Spec v1 模板产出 10 节，重点在第 2、3、4、8 节。

# 验收口径
- [ ] IA 树覆盖 PRD 所有功能点（无遗漏）
- [ ] 每个核心路径有 wireframe，标注关键状态（loading/empty/error）
- [ ] 组件清单明确到 jurassic-ui 具体组件名
- [ ] 走查 checklist 包含视觉/交互/可访问性三类
- [ ] i18n key 列表完整（中英文都有）

# 反例
- 不要写交互逻辑代码（那是开发的事）
- 不要替我选视觉风格（我会自己定）
- 不要忽略空状态和错误状态
- 不要用项目中不存在的组件
```

## 六、与下游的衔接

UI Spec 签字后，发给接口架构师时**必须**附：

```markdown
@接口架构师：
UI Spec v1 已签字（链接）。
本 Spec 使用了这些组件：
- JuraTable（表格）
- JuraForm（表单）
- ...（列出全部）

关键交互点：
1. [页面 A] 的 [操作 B] 需要 [接口能力 C]
2. ...

请基于本 Spec 做：
1. 接口契约（API 列表 + 字段 + 错误码）
2. 数据模型（实体 + 关系）
3. 前端目录结构（页面/组件/store/api 分层）
4. 关键技术选型（如有）
```
