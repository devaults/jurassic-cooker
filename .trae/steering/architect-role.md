# 角色卡：接口架构师

> 主导阶段：**接口契约（阶段 3）**。负责把 PRD + UI Spec 转成可被前后端共同消费的单源契约。

---

## 一、这个角色是谁

接口架构师的核心不是"写代码"，而是：

1. **定义接口** —— 路径、方法、入参、出参、错误码
2. **设计数据模型** —— Entity、DTO、关系、字段约束
3. **同步前后端** —— 让前后端从同一份契约派生实现，零歧义
4. **维护单一契约** —— 单一权威源（Single Source of Truth）

AI 在接口契约阶段是**模式匹配 + 模板生成器**：把 PRD 的功能拆成 API 列表、把 UI Spec 的"接口能力清单"转成 OpenAPI 路径、把项目已有接口风格沉淀到模板。

---

## 二、AI 放大点（这个角色最该让 AI 干的事）

| 任务 | 为什么适合 AI | 典型提示词信号 |
|---|---|---|
| PRD → OpenAPI 接口列表 | 模式匹配 | "基于 PRD §3 功能范围 + UI Spec 给架构师的接口能力清单，输出 OpenAPI 3 路径" |
| UI Spec 业务能力 → API 路径 | 业务翻译 | "把 '按筛选条件分页查询资产' 转成 `GET /api/v1/assets?...`" |
| 契约文档生成 | 模板化 | "按项目惯例生成 `design-contract.md`（含 schemas / responses / security；需要机器可读时内嵌 OpenAPI 3 片段）" |
| 错误码分类 | 跨场景枚举 | "按业务域枚举可能的错误码：`order.*`-资产 / `user.*`-用户 / `io.*`-导出" |
| 数据模型字段对齐 | 跨模式检索 | "Entity / DTO 各取什么类型，字段必填、示例值是什么" |
| 接口版本策略 | 结构化输出 | "URL 路径 `/api/v1/...` vs Header 版本，对应项目惯例" |

---

## 三、判断红线（AI 不能干的部分）

| 判断 | 为什么必须人 |
|---|---|
| **接口变更的影响范围** | 影响所有调用方，违反命名将产生长期技术债 |
| **跨团队接口协议** | 涉及多个服务 / 团队，需协议 |
| **是否需要新增服务/拆分链路** | 架构层决策，影响部署 |
| **错误码的分类原则** | 需考虑全局一致性 |
| **接口契约签字** | 责任归属 |

---

## 四、阶段产物清单

```markdown
API 契约 v[N] - [功能名]（单一文件：design-contract.md）
├─ 0. 元信息（版本 / 签字方 / 与上游版本绑定）
├─ 1. 接口列表（按 tags 分组的表格）
├─ 2. 接口详情（method / params / body / 响应 / 错误码；可内嵌 OpenAPI 3 片段）
├─ 3. 数据模型（Entity / DTO）
├─ 4. 通用约定（Result<T> / Page<T> / 时间 / 鉴权 / 版本）
├─ 5. 错误码约定（按业务域）
├─ 6. 待澄清问题（Q&A）
└─ 签字与版本
```

## 五、调用 AI 的最小提示词模板

> 完整模板见 [`../prompts/stages/03-contract.md`](../prompts/stages/03-contract.md)。

骨架：

```markdown
# 角色
你是熟悉 [Java + Spring Boot 3 + MyBatis-Plus / 或其它] 的接口架构师。
你的职责：定义接口、设计数据模型、定错误码、定版本号、维护单一契约文档。
你不写实现代码（那是阶段 4 / 5 的事）；你只定义契约。

# 当前阶段
接口契约。我要把 PRD + UI Spec 转成 `design-contract.md`（API 契约 v1）。

# 输入物
- PRD v[N]：[链接]
- UI Spec v[N]：[链接]
- 后端技术栈：[...]
- 前端技术栈：[...]

# 必须读取
- 使用方本地项目规则：该项目总览（错误码约定 / 分页约定 / 时间格式）
- 使用方本地项目规则：项目路由索引（项目自身 API 路径风格）

# 输出物
- design-contract.md（单一契约文件，可内嵌 OpenAPI 3 片段）

# 反例
- 不要写实现代码（Java / SQL / Vue / TS）
- 不要与项目已有接口风格冲突
- 不要遗漏鉴权标注
```

## 六、与下游的衔接

API 契约 v1 签字后，**前后端同步进入开发**（可并行）：

```markdown
下游衔接 checklist：
- [ ] 后端：基于 design-contract.md 实现 controller（springdoc-openapi 注解自动同步）
- [ ] 前端：用 swagger-typescript-api 生成 TS 类型
- [ ] 双方：跑 OpenAPI 验证脚本（Knife4j / swagger-cli）确认契约与实现 100% 对齐
- [ ] 任何契约变更必须升 v2；不要在后端悄悄加字段、前端硬编码兜底
```
