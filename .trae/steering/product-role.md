# 角色卡：产品设计

> 主导阶段：**需求分析**。负责把业务问题变成结构化 PRD + 验收口径。

---

## 一、这个角色是谁

产品设计的核心不是"画原型"，而是：

1. **定义问题** —— 这件事到底要解决谁的什么问题
2. **拆解场景** —— 用户在什么情境下、用什么路径完成
3. **定边界** —— 什么做、什么不做、什么延后
4. **设验收** —— 怎么算"做完了"

AI 在产品阶段是**结构化助手**：把口语需求拆成 PRD、把 PRD 拆成验收清单、把验收清单拆成 UI 能画的设计需求。

---

## 二、AI 放大点（这个角色最该让 AI 干的事）

| 任务 | 为什么适合 AI | 典型提示词信号 |
|---|---|---|
| 把会议纪要整理成 PRD 草稿 | 信息整合、模板化 | "把下面这段需求整理成 PRD v1 ..." |
| 从 PRD 抽验收清单 | 模式匹配、不漏项 | "列出本 PRD 的所有验收点 ..." |
| 找边界漏洞 | 跨场景枚举 | "列出本方案可能被吐槽的 5 个点 ..." |
| 类比已有产品方案 | 模式匹配 | "参考 [产品名] 的 [功能] 是怎么做的 ..." |
| 翻译成 UI 能画的 wireframe 描述 | 结构化输出 | "把这段需求转成 wireframe 文案描述 ..." |

---

## 三、判断红线（AI 不能干的部分）

| 判断 | 为什么必须人 |
|---|---|
| **要不要做这个功能** | 业务取舍，无客观标准 |
| **优先级排第几** | 涉及资源分配、跨团队博弈 |
| **对老用户的影响** | 需要完整业务上下文 |
| **和已有产品定位是否冲突** | 战略判断 |
| **PRD 签字** | 责任归属，不能让 AI 背锅 |

---

## 四、阶段产物清单（产品阶段必须交付）

```markdown
PRD v[N] - [功能名]
├─ 1. 背景与目标（why）
├─ 2. 用户与场景（who / when / where）
├─ 3. 功能范围（in-scope / out-of-scope）
├─ 4. 用户故事（user story list）
├─ 5. 业务流程（核心路径 + 异常路径）
├─ 6. 验收清单（checklist，每条可勾选）
├─ 7. 非功能需求（性能/安全/兼容）
├─ 8. 风险与依赖（哪些环节依赖外部）
├─ 9. 签字 + 版本号
└─ 10. 给 UI 的下一步指令
```

## 五、调用 AI 的最小提示词模板

> 完整模板见 [`../prompts/stages/01-requirement.md`](../prompts/stages/01-requirement.md)。

```markdown
# 角色
你是有 5 年 B 端产品经验的产品经理，专注 [业务域]。

# 当前阶段
需求分析。我要从一段口语需求整理出 PRD v1。

# 输入物
- 原始需求：[粘贴需求来源：会议纪要/用户反馈/老板要求...]
- 业务背景：[一句话]
- 已有产品参考：[同类功能/竞品链接]
- 项目上下文：<项目名（仓库名，如 oio-master-web；不写 group/ 前缀，见使用方项目注册表）>

# 输出物
按 PRD v1 模板产出 10 节内容，重点在第 3、4、6 节。

# 验收口径
- [ ] 范围边界清晰（in/out-of-scope 都写了）
- [ ] 用户故事覆盖核心路径 + 至少 2 个异常路径
- [ ] 验收清单每条都能在演示时被勾选
- [ ] 非功能需求给了具体数字（不是"快"而是"<200ms"）

# 反例
- 不要写技术方案（那是接口架构师 / 后端架构师的事）
- 不要画 UI 细节（那是 UI 设计的事）
- 不要替我签字
```

---

## 六、与下游的衔接

PRD 签字后，发给 UI 设计时**必须**附：

```markdown
@UI 设计：
PRD v1 已签字（链接）。
请基于本 PRD 做：
1. 信息架构（IA）：列出页面/模块层级
2. 关键页面 wireframe（每个核心路径至少一张）
3. 交互流程图（核心路径 + 异常路径）
4. UI 走查 checklist
```

下游没回执 = PRD 没传达到位，产品阶段不算完成。

## 附录：产品常用 AI 提示词片段

| 场景 | 提示词片段 |
|---|---|
| 把会议纪要整理成 PRD | "把下面这段会议纪要整理成 PRD v1 结构，缺什么问什么" |
| 找漏洞 | "作为挑剔的产品总监，列出本 PRD 可能被挑战的 5 个点" |
| 拆用户故事 | "把第 3 节功能范围拆成用户故事，每条格式：作为 [角色]，我想要 [功能]，以便 [价值]" |
| 写验收清单 | "把第 4 节每个用户故事转成可勾选的验收点" |
| 类比方案 | "参考 [产品名] 的 [功能名]，给本 PRD 一个交互模式建议" |
