# 故障复盘文档结构

> 跨端、跨角色通用。任何事故（线上 / 准线上 / 严重 Bug）后都应写。
> 复盘原则是 **blameless（无指责）**：聚焦系统与流程，不找人。

---

## 0. 为什么要做复盘

- **避免重复事故**：不写 = 注定重演
- **跨团队知识沉淀**：下次遇到类似问题有据可查
- **流程改进的输入**：action items 推动系统/工具/流程升级
- **客户信任**：坦诚 + 行动 = 信任；遮掩 = 失信

---

## 1. 何时该写复盘

| 触发 | 严重度 | 是否必写 |
|---|---|---|
| 影响生产的 P0/P1 事故 | 高 | **必写**（一周内） |
| 影响生产但自动恢复 | 中 | **必写** |
| 准线上（压测 / 灰度 / 内测）发现重大问题 | 中 | **必写** |
| 测试环境 P1 故障影响开发 | 低 | 建议写 |
| 单个用户反馈的边缘 case | 低 | 写到 issue 即可，不写复盘 |
| 个人手抖造成的本地 bug | 低 | 不写 |

---

## 2. 严重度分级

| 级别 | 影响范围 | 持续时间 | 例子 |
|---|---|---|---|
| **P0** | 全量用户 | > 30 分钟 | 主流程完全不可用 |
| **P1** | 全量或大批量用户 | > 1 小时 | 核心功能不可用 / 数据错误 |
| **P2** | 部分用户 / 部分功能 | 任意 | 非核心功能不可用 / 性能严重下降 |
| **P3** | 边缘用户 / 边缘场景 | 任意 | 单点报错 / UI 错位 |

## 4. 根因分析（Root Cause）

### 4.1 直接原因

<技术层面直接导致事故的原因>

### 4.2 根本原因（5 Whys）

<!-- 用 5 Whys 追问，直到挖到系统/流程层 -->

1. **为什么 API 5xx 飙升？** → v1.2.3 引入的 SQL 有 N+1 问题
2. **为什么 N+1 没被测出来？** → 压测没模拟真实数据量
3. **为什么压测不真实？** → 测试环境数据只有生产 1%
4. **为什么没监控到 N+1？** → 慢查询监控阈值 5s，N+1 单条 < 100ms
5. **为什么阈值是 5s？** → 历史默认值，没人按业务调整

**系统级根因**：监控阈值 + 压测数据量都是"历史默认值"，**没人定期 review 是否还匹配当前业务**。

### 4.3 贡献因素（Contributing Factors）

- 缺少 PR 评审 checklist（数据库改动必须压测）
- 告警通知走 Slack，但值班同学在会议中
- 没有"5xx > 1% 自动告警"，等到 5% 才告警

## 5. 为什么没拦住

<!-- 列出应该拦住事故的"门"以及为什么没拦住 -->

| 防御层 | 期望 | 实际 | 为什么没拦住 |
|---|---|---|---|
| 单元测试 | 覆盖 SQL | 18% 覆盖 | 老代码未补 |
| 集成测试 | 跑真实数据 | 1% 数据量 | 测试环境数据少 |
| 压测 | 模拟峰值 | 未跑 | 没人触发 |
| 灰度 | 1% → 100% | 直接 100% | 上线流程未走灰度 |
| 监控 | 5xx > 1% 告警 | 5xx > 5% 才告警 | 默认阈值过宽 |
| 告警通知 | 立即送达 | 5 分钟延迟 | 通知渠道未配置 |

## 6. 响应评估

- **响应速度**：<从告警到响应 X 分钟>（目标 < 5 分钟）
- **沟通质量**：<Slack 频道活跃 / 上下游同步及时>
- **决策质量**：<回滚决策果断 / 拖了 X 分钟才决定>
- **恢复速度**：<X 分钟恢复>
- **改进点**：<下次需要更快的环节>

## 7. 改进措施（Action Items）

<!-- 必填；用 SMART 原则 -->

| # | 类别 | 措施 | 责任人 | 截止 | 状态 |
|---|---|---|---|---|---|
| A1 | 监控 | 5xx 告警阈值从 5% 改 1% | @A | 本周 | ☐ |
| A2 | 测试 | 压测环境数据同步到生产 30% | @B | 2 周 | ☐ |
| A3 | 流程 | DB 改动必须走灰度 | @C | 1 周 | ☐ |
| A4 | 工具 | 加 SQL N+1 自动检测（p6spy） | @A | 1 月 | ☐ |
| A5 | 文档 | 把"5xx 阈值调整"写到 runbook | @D | 1 周 | ☐ |

> **类别**：监控 / 测试 / 流程 / 工具 / 文档
> **优先级**：A 类必须做 / B 类应该做 / C 类想做

## 8. 经验教训（Lessons Learned）

<!-- 提炼出可复用的认知，不仅限本次 -->

1. **"默认值"是隐藏的债务**：监控阈值 / 压测数据量 / 重试次数都需要随业务演进
2. **"压测不真实"是最大的压测盲点**：不如不压
3. **直接回滚 > 现场 hotfix**：除非根因一眼可见
4. **5 Whys 一定要追问到系统层**：到个人就停 = 找替罪羊

## 4. 关键原则

### 4.1 Blameless（无指责）

| ✓ 好 | ✗ 差 |
|---|---|
| "监控阈值是历史默认值，未随业务调整" | "@A 没配监控阈值" |
| "压测流程未规定数据量" | "@B 没认真做压测" |
| "上线流程未走灰度" | "@C 直接上了 100%" |
| "5 Whys 挖到系统层" | "@A 犯了个低级错误" |

> 系统的失败 vs 个人的失误：
> - 一个人能犯的错 = 系统没防住
> - 同一类错反复犯 = 流程没改

### 4.2 5 Whys 必须挖到底

- 第 1-2 层通常是**技术症状**（SQL N+1、阈值太宽）
- 第 3-4 层通常是**流程问题**（压测没跑、上线没灰度）
- 第 5 层通常是**系统问题**（默认值、工具缺口、组织协作）
- **到第 3 层就停** = 找替罪羊；**到第 5 层** = 真正改进

### 4.3 Action Items 必填且 SMART

| 维度 | 含义 | 例子 |
|---|---|---|
| S（Specific） | 具体做什么 | "5xx 告警阈值从 5% 改 1%" |
| M（Measurable） | 怎么算完成 | "Prometheus 规则更新 + 告警测试通过" |
| A（Attainable） | 现实可做 | 1 周内能做完 |
| R（Relevant） | 与根因直接相关 | 是 |
| T（Time-bound） | 有截止 | 本周内 |

### 4.4 时间线要带时区

- **统一时区**（推荐 UTC+8）
- **关键节点**：部署、告警、首次响应、根因定位、临时修复、根本修复、监控恢复
- **空档要写**（"14:35-14:40 等待值班同学确认"也算事件）

## 5. 流程：复盘什么时候开

| 时间 | 动作 |
|---|---|
| 事故中 | 先恢复，后复盘（不在救火时写复盘） |
| 恢复后 24h 内 | 写"事件初报"（简版时间线 + 临时措施） |
| 恢复后 1 周内 | 召开复盘会 + 写完整复盘文档 |
| 复盘会后 1 周内 | action items 责任人确认 + 截止日期确认 |
| 1 个月后 | 跟进 action items 进度，关闭完成的 |

---

## 6. 复盘会议怎么开

| 环节 | 时长 | 主持 | 内容 |
|---|---|---|---|
| 时间线 | 10 分钟 | 事故 owner | 按时间线还原（不留盲区） |
| 5 Whys | 20 分钟 | 全员 | 集体追问到系统层 |
| Action Items | 15 分钟 | 主持 | 列出改进措施 + 责任人 + 截止 |
| 总结 | 5 分钟 | 主持 | 感谢参与，强调 blameless |

> **不要**在复盘会讨论"谁的责任"——那是 HR 范畴。

## 7. 文档存放与传播

| 类型 | 位置 |
|---|---|
| 公开事故（影响外部） | 团队 wiki + 官方公告（脱敏） |
| 内部事故 | 团队 wiki 私密区 |
| 跨团队事故 | 团队 wiki 公开区 + 跨团队分享会 |
| 监管报告要求 | 法务 / 合规接口人同步 |

> **脱敏原则**：保留技术细节；脱敏用户数据、商业数据、个人信息。

## 8. 反例（不该写的复盘）

```diff
- "是 @A 的失误"
- "测试没测到"                          # ✗ 没说为什么没测到
- "5 Whys 到了第 2 层"                  # ✗ 没挖到底
- "改完就好"                            # ✗ 没 action items
- "以后小心点"                          # ✗ 没有可执行措施
- "所有人都没注意到"                     # ✗ 找替罪羊
- "这是不可抗力"                        # ✗ 必有改进空间
- "我个人认为"                          # ✗ blameless 是规则不是观点
```
