# 阶段 2：界面设计（UI 主导）

> 输入：PRD v1（已签字）
> 输出：**UI Spec v1（视觉部分）** —— 不含接口契约、接口能力列表放到阶段 3 由架构师主导
> 主导角色：[UI 设计](../../steering/ui-role.md)
> 路线：被 [`full-pipeline`](../routes/full-pipeline.md) 与 [`both-ends`](../routes/both-ends.md) 引用

---

## 与"前后端拆分"的设计

UI 阶段**只产出视觉与交互部分**（IA / 组件清单 / 视觉规范 / 走查 checklist）。
**接口契约**（API 路径 / 字段 / 错误码 / 版本）由 [阶段 3 接口契约](../../steering/architect-role.md) 主导；UI 阶段不写 API 细节。
UI 阶段给架构师的产物是**"需要哪些接口能力"**（业务能力清单），不是"接口路径"。

## 完整提示词模板（复制后填空）

```markdown
# 角色
你是有 5 年 B 端 UI 设计经验的设计师，熟悉 jurassic-ui 2.x 组件库与 juraTheme 主题。
你的风格：组件复用优先、不造轮子、空状态/错误状态从不遗漏、对响应式敏感。

# 当前阶段
界面设计。我要把 PRD v[N] 拆成 UI Spec v1（仅视觉与交互部分）。

# 输入物
## PRD v[N]
[链接或粘贴关键章节：功能范围、用户故事、业务流程、验收清单]

## 项目上下文
- 路径：<项目名（仓库名，如 oio-master-web；不写 group/ 前缀，见使用方项目注册表）>
- 技术栈：[Vue 3 + Vite + TS + jurassic-ui 2.x / 或其它]
- 响应式要求：[仅 PC / PC+Pad / PC+Pad+手机]

## 必须读取（AI 必须先读这些再开工）
- .trae/skills/frontend/jurassic-ui/SKILL.md（组件能力地图）
- .trae/rules/frontend/lang/css.md（CSS 规范、juraTheme 主题）
- .trae/skills/frontend/i18n-workflow/SKILL.md（如有国际化）
- .trae/skills/frontend/crud-page/SKILL.md（如涉及列表/表单）
- 项目实际组件库源码：<项目内 packages/ 或 node_modules/jurassic-ui/ 路径>

# 输出物
请按 UI Spec v1 模板产出 10 节内容，重点在第 2、3、4、8 节：

1. 信息架构（IA 树）—— 页面 / 模块 / 操作 三级
2. 关键页面 wireframe
   - 每个核心路径至少一张
   - 每张标注：loading / empty / error 三种状态
   - 用文字描述（不是图），便于 AI 后续转代码
3. 交互流程图
   - 核心路径（happy path）
   - 异常路径（至少 2 个）
   - 边界场景（空数据 / 极值 / 并发）
4. 组件清单 —— 必须明确到 jurassic-ui 具体组件名（如 JuraTable / JuraForm / JModal）
5. 视觉规范
   - 间距（用 juraTheme token：spacing.xs/sm/md/lg/xl）
   - 字号（fontSize.sm/md/lg/xl）
   - 颜色（text.primary / text.secondary / brand.primary）
6. 响应式断点
   - 桌面：≥ 1200px
   - 平板：768-1199px
   - 手机：< 768px（如需）
7. 文案规范
   - i18n key 列表（中英文都有）
   - 按钮 / 提示 / 空状态文案
8. 走查 checklist
   - 视觉（间距/字号/颜色一致性）
   - 交互（hover/focus/disabled/loading 反馈）
   - 可访问性（键盘/对比度/aria-label）
   - 边界（空/极值/错误/并发）
9. [签字 + 版本号] —— 留空，由人填
10. 给架构师 / 前端的**接口能力清单**（不是 API 路径）
    - 列出本 UI Spec 用到的所有组件
    - 列出关键交互点 → 需要哪些业务接口能力（用业务语言，例如"按筛选条件分页查询资产"、"按选中字段批量导出 Excel"）
    - 列出至少 3 个需要架构师回答的问题（数据来源 / 权限 / 性能）

# 验收口径
- [ ] IA 树覆盖 PRD 所有功能点（无遗漏）
- [ ] 每个核心路径有 wireframe，标注 3 种状态（loading/empty/error）
- [ ] 组件清单明确到具体组件名（不写"表格组件"，写"JuraTable"）
- [ ] 视觉规范用 juraTheme token，不写魔法值
- [ ] i18n key 列表完整（中英文都列了）
- [ ] 走查 checklist 包含视觉/交互/可访问性/边界四类
- [ ] **给架构师的接口能力清单**列出至少 3 个业务能力（用业务语言，非 API 路径）

# 反例（不该做的事）
- 不要写交互逻辑代码（那是前端开发的事）
- 不要写 API 路径 / 字段 / 错误码（那是架构师阶段 3 的事）
- 不要替我选视觉风格/品牌色（我会自己定）
- 不要忽略空状态和错误状态（任何列表/表单都必须有）
- 不要用项目里没有的组件（必须先读 jurassic-ui 源码确认）
- 不要硬编码颜色（用 juraTheme token）
- 不要遗漏 i18n（任何用户可见文案必须有 key）
```

## 怎么用

1. **复制上方整段** → 替换方括号内容 → 整段发给 AI
2. **AI 输出后** → 逐项对照"验收口径"打勾
3. **不通过项** → 让 AI 修订
4. **通过后** → 人签字 + 给版本号 `UI Spec v1` → 进入[阶段 3 接口契约](./03-contract.md)（若涉及后端）或直接进入[阶段 5 前端开发](./05-dev-frontend.md)（若仅前端）

## 下游衔接

- **若仅前端**：UI Spec 直接进 [阶段 5 前端开发](./05-dev-frontend.md)；前端开发从后端拿 API 文档后开工
