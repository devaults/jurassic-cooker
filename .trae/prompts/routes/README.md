# routes/ — 按"路线"使用阶段提示词

> **用途**：在 [`../README.md`](../README.md) 选了路线后，到这里来按顺序使用提示词。
> 单阶段提示词见 [`../stages/`](../stages/)。

## 路线一览

| 路线 | 适用场景 | 提示词顺序 |
|---|---|---|
| [`plan-only.md`](./plan-only.md) | 小任务 / 日常迭代（改 bug、单接口迭代、单模块小改） | 调查 → 计划 → 确认 → 执行 → 交卷（单文件，无阶段） |
| [`frontend-only.md`](./frontend-only.md) | 接到后端 API 文档 / Swagger，只做前端 | 接口契约（已有）→ 前端开发 → QA |
| [`backend-only.md`](./backend-only.md) | 接到产品需求 + 接口契约，只做后端 | 接口契约（已有）→ 后端开发 → QA |
| [`both-ends.md`](./both-ends.md) | 一个功能前后端都做（小功能 / 一人全包） | 接口契约（自产出）→ 后端 + 前端（并行）→ QA |
| [`full-pipeline.md`](./full-pipeline.md) | 完整从需求到上线（团队协作 / 大功能） | 需求 → UI → 接口契约 → 后端 + 前端（并行）→ QA |

## 关键概念

- **接口契约**：前后端的**强制同步点**（阶段 3）。未签字的 API 契约，前后端不得开工。
- **Plan 通道**：小任务走 `plan-only`，只产 `plans/` 单文件计划（与 `specs/` 平级），免签、不分阶段；命中升级闸口（跨 2+ 项目仓 / 改契约 / 需独立 QA 或签字 / > 5 卡片 / > 10 文件）转完整路线。
- **个人通道例外**：个人 spec / 个人 plan 落**外置个人根**（本机 `config.local.yaml` 的 `spec.personal.root`），不共享、免签字，上述同步闸口不适用。
- **可并行**：接口契约 v1 签字后，后端开发（阶段 4）与前端开发（阶段 5）可并行进行。
- **QA 是必经**：无论走哪条路线，QA（阶段 6）都是最后环节。

## 选路速查

```
你今天要干啥？
├─ 小任务 / 日常迭代（改 bug、单接口、单模块小改） → plan-only
├─ 接到后端 API 文档了 → frontend-only
├─ 接到产品 PRD + 接口契约了 → backend-only
├─ 一个功能前后端都做（小功能，both-ends
├─ 从零开始，大功能，团队协作 → full-pipeline
└─ 补某个阶段（如回头补接口契约） → 直接看 stages/ 对应文件
```
