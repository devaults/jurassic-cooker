# 路线 1：只做前端（最常见）

> **场景**：你已接到后端给出的 API 文档 / Swagger / 已签字的 `API 契约 v1`，只负责前端实现。

## 适用判定

✅ 你拿到了：
- 已签字的 `API 契约 v1`（`design-contract.md`）
- UI Spec v1（如有，没有也不影响产品需求）
- 后端开发完成时间（让前端联调有节奏）

❌ 不适用：需要改接口契约 → 走 [`both-ends.md`](./both-ends.md) 或 [`full-pipeline.md`](./full-pipeline.md)

## 提示词顺序

| 顺序 | 阶段 | 提示词 | 备注 |
|---|---|---|---|
| 1 | 接口契约（核对） | [`../stages/03-contract.md`](../stages/03-contract.md) | **不必重新产出**，而是核对"我手上的契约 v1 与项目一致"，作为前端工作的输入 |
| 2 | 前端开发 | [`../stages/05-dev-frontend.md`](../stages/05-dev-frontend.md) | 主战场 |
| 3 | QA | [`../stages/06-qa.md`](../stages/06-qa.md) | 跑端到端 |

> **顺序 1 的"核对"**：你手上如果是后端的 Swagger 文档，可能与项目组的 `API 契约 v1` 有偏差；先与后端确认无歧义再开工。

## 关键纪律

- **不私自改接口**：前端调任何字段都得在契约 v1 中存在；如发现契约漏洞 → 退回后端改契约（升级到 v2）→ 不要在前端硬编码兜底
- **优先用 `swagger-typescript-api` 生成**：不要手抄接口类型
- **联调时遇到字段不一致**：80% 是契约没更新 → 第一时间沟通
