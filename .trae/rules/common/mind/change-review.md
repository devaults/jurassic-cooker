# Change & Review：变更管理与交卷

> **强制**：改前做影响分析，改后做代码自检，交卷时如实报告。
> 不越界改动见 [`self-harness.md`](./self-harness.md) §4。

## 一、变更前

### 1. 影响分析（强制）

改这些之前**必须先搜索引用**，并在回复中说明影响面：

函数签名、组件 `props`/`emits`、导出名、公共样式类名、工具函数、store 模块、API 接口函数、路由 `name`/`path`、i18n key。

**删除代码/文件前确认无引用。**

### 2. 第三方代码策略
- ❌ 禁止直接修改 `node_modules/`
- 样式不符 → CSS 覆盖（`:deep()` 或全局样式）
- 缺功能 → 包装组件透传 props
- 有 bug → `patch-package` 打补丁，`patches/` 提交 Git

### 3. 最小改动的例外

**仅以下情况可以扩大范围**：用户明确要求、不改会导致当前修改无法工作、
发现影响当前功能的明确 bug（按 [`context-collaboration.md`](./context-collaboration.md) §1 先告知）。

### 4. 回滚意识
高风险改动前主动提醒用户：核心业务逻辑（支付/权限/数据写入）、跨 5+ 文件重构或删除 >50 行、
构建配置 / 依赖版本 / 全局样式 / 全局状态 / 路由守卫。

### 5. 先理解再修改

改陌生模块前必读：入口文件、调用链、数据流、周边代码模式。
禁止：看到报错就注释掉、不理解就加 try-catch。

### 6. 要不要新建文件
- **要新建**：独立业务逻辑 >100 行、多处复用的组件/工具/类型、现有文件 >500 行
- **不要新建**：单处用的小组件 <50 行、单文件用的工具函数、1-2 个类型定义

## 二、变更后自检

> lint / typecheck 通过后逐项自问——自动化工具查不出逻辑漏洞。
> **本清单只管代码层自检**；功能/验收层（列表空态、弹窗二次打开、分页、权限按钮等）与交卷话术见
> [`skills/frontend/quality-review`](../../../skills/frontend/quality-review/SKILL.md)，两者不重复。

- **边界**：空值（`null`/`undefined`/`""`/`[]`/`{}`）有防御？极值（0、负数、超大数组、超长字符串）？
  异步回调时组件是否已卸载（abort / isMounted）？深层属性用 `?.` 或提前判断？
- **内存**：监听、定时器、Observer、WebSocket、AbortController、事件总线是否成对释放？
  ⚠️ 成对清单与模板见 [`api-cleanup.md`](../../frontend/mind/api-cleanup.md) §八，此处不重复
- **错误处理与提示**：失败是否用户可感知、取消是否静默、Loading 是否关闭？
  ⚠️ 策略见 [`api-cleanup.md`](../../frontend/mind/api-cleanup.md) §三、§四
- **安全**：XSS、敏感信息、外链、密钥 → 逐项清单见 [`eng/security.md`](../../frontend/eng/security.md)
- **Vue 模板**：key、`v-if`/`v-for` 等模板规范 → 见 [`lang/vue.md`](../../frontend/lang/vue.md) §一
- **回归**：改动的函数/组件被谁引用（搜引用确认）？公共工具/composable 影响其他调用方？
  影响已上线功能时跑该项目 E2E 用例或按回归清单核对（见使用方本地用例清单）
- **体验**：空列表有占位？

### 输出格式

`自检结果：边界✓ 内存✓ 错误✓ 安全✓ 回归：已查N处引用无影响`
1-2 行的样式/文案改动可简化为"自检通过"。

## 三、交卷口径（强制）

声称"做完"必须写清四件事：

1. 改了哪些文件 / 路由
2. **实际执行了哪些命令及结果**
3. 未做项（接口未就绪、权限码未知、设计稿缺失）
4. 阻塞点

没跑的命令不写成跑过，没验证的不写"已验证"；实现与验证不一致时先说验证结果。
完整清单 → [`skills/frontend/quality-review`](../../../skills/frontend/quality-review/SKILL.md)
